# ESQUEMA TÉCNICO COMPLETO Y ACTUALIZADO DE COLECCIONES EN WIX CMS

**Proyecto:** MARIANMADRID4001 / MARIANMADRID4002
**Versión de Arquitectura:** v21.0.0-LTS
**Estándar de Nomenclatura:** Nombre visible en MAYUSCULAS_CON_GUION_BAJO | ID interna de colección según SSOT (internalConfig.js) | Campos en camelCase / ID exacta | Claves foráneas sin traducir.

---

## 🧭 1. REGLAS DE NOMENCLATURA, TIPOS Y PERMISOS

1. **Nombre Visible de Colección:** Siempre en MAYUSCULAS_CON_GUION_BAJO (ej. SERVICIOS_RESERVA, MOVIMIENTO_CAJA, REGISTRO_HORARIO).
2. **Identificador Interno (collectionId):** Cadena técnica exacta consumida por las APIs de wix-data en el backend.
3. **Identificadores Nativos (Invariables):** Los campos que enlazan con APIs nativas de Wix nunca se traducen (serviceId, bookingId, resourceId, scheduleId, locationId, orderId, checkoutId, productId, variantId, sku).
4. **Niveles de Permisos en Wix CMS:**
   - Público (Anyone): Lectura abierta para catálogo y disponibilidad pública.
   - Miembro (SiteMember): Fichajes propios, consultas de empleado o pedidos de usuario autenticado.
   - Administrador (Admin) / Sistema Backend: Escritura protegida, auditoría, contabilidad, ledger inmutable y crones con elevación (suppressAuth: true).

### Detalle de Relaciones:

1. **SERVICIOS_RESERVA → CATEGORIAS_SERVICIO** (1:1 / Reference):
   - Campo: `nombreCategoria`
   - Comportamiento: En el CMS se visualiza y selecciona el nombre comercial (PELUQUERIA MUJER, COLOR PROFESIONAL, etc.), vinculando el registro maestro de categoría.

2. **SERVICIOS_RESERVA → MAPA_STAFF** (1:N / Multi-Reference):
   - Campo: `personalDisponibleNombres`
   - Comportamiento: Permite asociar una o varias estilistas autorizadas para impartir el servicio. El backend resuelve la disponibilidad nativa en Wix Bookings cruzando con resourceId.

3. **SERVICIOS_RESERVA → ADDONS_CATALOGO** (1:N / Multi-Reference):
   - Campo: `addOnTitles`
   - Comportamiento: Define qué complementos o tratamientos adicionales son compatibles con el servicio principal.

4. **SERVICIOS_RESERVA → SERVICIOS_RESERVA** (1:1 / Auto-Referencia Reflexiva):
   - Campo: `tituloServicioFaseDos`
   - Comportamiento: En servicios duales (con tiempo de exposición intermedio), enlaza el servicio de Fase 1 con su correspondiente sub-servicio de Fase 2 (ej. Babylights F1 → F2-Babylights: Aclarado y Matizado).

5. **SERVICIOS_RESERVA → LOCALIZACIONES_SALON** (1:1 / Reference):
   - Campo: `location`
   - Comportamiento: Vincula el servicio al salón físico autorizado (Salón Central Zaragoza).

6. **CITAS_F2 → MAPA_STAFF** (1:1 / Clave Foránea resourceId):
   - Comportamiento: Cada reserva almacena el resourceId de la estilista asignada tras resolver el balanceo de carga por minutos de trabajo diarios.

7. **MOVIMIENTOS_CAJA → CITAS_F2** (1:1 / reservaIdVinculada):
   - Comportamiento: Asocia el cobro o abono fiscal con la(s) cita(s) de Bookings V2 mediante el bookingId o pairToken.

8. **ASIENTOS_CONTABLES → MOVIMIENTOS_CAJA** (1:1 / sourceId):
   - Comportamiento: Cada movimiento de caja confirmado genera de manera determinista un asiento contable cuadrado en Debe y Haber.

| Colección Eliminada / Prescindible | Destino Arquitectónico | Instrucción para Refactorización de Código |
| :--- | :--- | :--- |
| **`CONCILIACION_STOCK_WIX`** | Colección **`MOVIMIENTOS_INVENTARIO`** | Sustituir consultas a `ConciliacionStockWix` por consultas a `MovimientosInventario` filtrando por `.eq("requiresWixReconciliation", true)`. |
| **`SYNC_M365`** | Colección **`M365_GRAPH_SYNC_QUEUE`** | Redirigir lecturas de logs históricos a `M365GraphSyncQueue` consultando registros con `.hasSome("status", ["COMPLETED", "FAILED"])`. |
| **`AVAILABILITY_SLOTS_CACHE`**| Colección **`DUAL_SLOT_CACHE`** | Redirigir lecturas de franjas cacheadas a `DualSlotCache` o consultar la disponibilidad en memoria edge mediante `wix-web-module` (`cache: { tags, ttl }`). |
| **`BOOKINGS_SERVICE_SYNC_QUEUE`**| Colección **`BOOKING_TRANSACTIONS`** | Encaminar las tareas asíncronas de sincronización a `BookingTransactions` utilizando `serviceId` y `desiredHash`. |
| **`MUTEXES`** | **Motor de reservas nativo V2** | Eliminar inserciones y lecturas en `MmLocks`. Capturar el rechazo transaccional de Wix Bookings V2 cuando devuelva el error nativo `SLOT_NOT_AVAILABLE`. |
| **`COMPLEMENTOS_CATALOGO`** | **Wix Bookings V2 Add-ons API** | Sustituir consultas CMS a `ComplementosCatalogo` por llamadas al SDK `@wix/bookings` mediante `services.getService()` inspeccionando `service.addOnGroups` y `service.addOns`. |
